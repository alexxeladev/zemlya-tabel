## ПУНКТ 1 — Премии и KPI с обоснованием

В табеле у сотрудника можно добавлять премии и KPI — суммы в рублях, которые прибавляются к выплате.

**Поведение:**
- В строке сотрудника (в финансовой части) — возможность добавить премию и/или KPI кнопкой «+» (как сейчас добавляются слоты в днях)
- Премия — сумма в рублях
- KPI — сумма в рублях (отдельно от премии)
- При добавлении каждой суммы **обязательно поле «Обоснование»** (текст). Без обоснования не сохранять (валидация)
- У сотрудника может быть несколько премий/KPI за месяц (каждая со своим обоснованием) ИЛИ одна сумма с обоснованием — выбери что проще и логичнее; если несколько, они суммируются
- Премии и KPI привязаны к сотруднику + период (год/месяц)
- Видны и редактируются: admin, accountant, manager (своего отдела). Employee не видит.

**Модель данных:**
- Новая таблица для премий/надбавок: employee_id, year, month, type (premium/kpi), amount (Decimal), reason (text), created_by, created_at
- Создать миграцию, применить, проверить alembic current = head

**Расчёт:**
- Премии и KPI прибавляются к итоговой выплате сотрудника (см. пункт 4)

## ПУНКТ 2 — Удержания: займ и аванс

Два вида удержаний из зарплаты.

### Займ (в карточке сотрудника)

- В карточке сотрудника — признак «Займ»: сумма займа (Decimal) + срок в месяцах (int) + дата начала погашения
- Займ гасится автоматически равными долями: `ежемесячное_удержание = сумма_займа / срок`
- Каждый месяц в период удерживается эта доля, пока займ не погасится (число месяцев = срок)
- **Бухгалтер может вручную скорректировать сумму удержания за конкретный месяц** (например в этом месяце удержать меньше). Ручная правка не меняет общий график, только сумму этого месяца.
- Нужно отслеживать остаток займа (сколько ещё осталось погасить)

**Модель:**
- Поля займа в карточке сотрудника (или отдельная таблица loan): сумма, срок, дата начала, остаток
- Таблица помесячных удержаний по займу: employee_id, year, month, planned_amount, actual_amount (если бухгалтер поправил), создаётся при расчёте
- При погашении (остаток = 0) — займ закрыт, удержания прекращаются

### Аванс (разовое удержание)

- Аванс — это удержание: сотруднику выдали деньги раньше, теперь вычитается из зарплаты
- Вводится в табеле/расчёте за конкретный месяц как сумма
- Разовое (не повторяется автоматически)
- Привязан к сотруднику + период

**Модель:**
- Можно в той же таблице что премии (с type=advance_deduction) или отдельной — на твой выбор. Аванс — отрицательный вклад в выплату.

## ПУНКТ 4 — В сводной: «Удержано ₽» и «К выплате ₽»

Сейчас в финансовой части есть «Итого ₽». После неё добавить две колонки/строки:

- **Удержано ₽** = доля займа за месяц (с учётом ручной правки) + аванс
- **К выплате ₽** = Итого ₽ + премии + KPI − Удержано

Формула «К выплате»:
```
К выплате = Итого_начислено (оклад + переработка + праздничные) + Премии + KPI − Удержано
```
где Удержано = займ_доля + аванс.

Показывать в строке сотрудника и в итоговой строке (сумма по всем).

Видно: admin, accountant, manager (свой отдел). Не employee.

## Acceptance criteria

1. **Премии/KPI**: в табеле можно добавить премию и KPI с обязательным обоснованием. Без обоснования — не сохраняется. Суммы прибавляются к выплате.
2. **Займ**: в карточке сотрудника задаётся сумма + срок. Автоматически удерживается доля каждый месяц. Бухгалтер может поправить сумму за месяц. Остаток уменьшается, при 0 — займ закрыт.
3. **Аванс**: разовое удержание за месяц, вычитается.
4. **Коэффициент**: в табеле виден коэффициент/ставка сотрудника.
5. **Сводная**: после «Итого ₽» видны «Удержано ₽» и «К выплате ₽». К выплате = Итого + премии + KPI − удержано. Суммы сходятся.
6. **Excel порядок**: № → Таб.№ → ФИО.
7. **Excel подсветка**: строки читаемо подсвечены.
8. Роли: employee не видит финансовых сущностей. Manager видит свой отдел.
9. `pytest -v` зелёный, включая новые тесты на займ (автопогашение, ручная правка, остаток) и расчёт «к выплате».

## Подводные камни

- **Decimal для денег** — все суммы Decimal, ROUND_HALF_EVEN. Не float.
- **Миграции** — после создания обязательно alembic upgrade head + проверка alembic current = head. SQLite-тесты проходят даже без применения миграции, маскируя расхождение с Postgres.
- **Займ — граничные случаи**: последний месяц (остаток меньше обычной доли — удержать остаток, не больше), досрочное погашение, займ начат в середине срока.
- **Ручная правка займа** не должна ломать общий остаток — если бухгалтер удержал меньше, остаток гасится медленнее (или срок продлевается — уточни у меня если неясно, но по умолчанию: остаток = сумма − фактически удержанное суммарно).
- **Несколько премий** у одного сотрудника — суммируются корректно.
