# Задача 4.1 — Дашборд (Этап 4)

## Контекст

Этап 3 закрыт: табель, workflow, расчёт ЗП, экспорт работают. Теперь — **дашборд**: сводная аналитика для руководства. Графический, интерактивный, с разными представлениями для разных ролей.

Задача намеренно НЕ указывает имена конкретных функций, переменных, файлов. Сначала разберись в текущем коде (модели, сервисы расчёта ЗП, видимость по ролям), потом реализуй. Действуй по правилу 3 попыток.

Перед началом — бэкап БД:
```bash
mkdir -p ~/backups
docker exec -t $(docker ps -q -f ancestor=postgres:16) pg_dump -U tabel tabel > ~/backups/before_4_1_$(date +%s).sql
```

## Общая концепция

Дашборд — главная страница при входе (уже есть пункт «Дашборд» в sidebar, сейчас вероятно заглушка). Наполняем его реальными данными.

**Формат:** карточки с ключевыми цифрами сверху + графики (столбцы и линии) ниже. Используй библиотеку recharts (она в стеке проекта). Дизайн — чистый, читаемый, в стиле существующих страниц (Tailwind).

**Интерактивность:** карточки отделов кликабельны — клик ведёт на страницу табеля с фильтром на этот отдел и текущий период.

**Роли — каждая видит своё:**

| Роль | Что видит на дашборде |
|---|---|
| admin (собственник/гендир) | Вся компания: все отделы, весь ФОТ, все статусы, динамика по всем |
| accountant | Контроль закрытия периодов (статусы) + ФОТ по всем отделам и компаниям |
| manager | Только свой отдел: часы, ФОТ, статус, динамика своего отдела |
| employee | Свои часы за период (простой персональный виджет, без финансов) |

## Четыре блока дашборда

### Блок 1 — Часы (отработано / норма / переработка)

**Карточки сверху (KPI):**
- Всего отработано часов (за выбранный месяц)
- Норма часов
- Переработка часов
- Процент выполнения нормы

**График:** столбчатая диаграмма «Часы по отделам»:
- Ось X — отделы
- Для каждого отдела — сгруппированные столбцы: Норма / Отработано / Переработка
- Для manager — только его отдел (или вообще без разбивки по отделам, просто его сотрудники)

### Блок 2 — ФОТ (фонд оплаты труда)

**Карточки:**
- Всего начислено за месяц (общий ФОТ)
- В т.ч. оклады
- В т.ч. переработка
- В т.ч. праздничные

**Графики:**
- Столбчатая «ФОТ по отделам» (сумма начислений на каждый отдел)
- Круговая или столбчатая «ФОТ по компаниям» (сколько начислено с каждого юрлица)

ФОТ виден admin, accountant, manager (свой отдел). Employee — НЕ видит ФОТ.

### Блок 3 — Статусы периодов

**Карточки:**
- Периодов закрыто (за текущий месяц)
- На проверке
- В черновике
- Просрочено (если период за прошлый месяц всё ещё не закрыт — это просрочка)

**Визуализация:** список/таблица отделов со статусом периода:
- Отдел | Период | Статус (цветной бейдж) | Кто отправил/закрыл | Действие

Каждая строка кликабельна → переход в табель этого отдела.

Для accountant этот блок — главный (контроль закрытия). Для manager — только статус своего отдела.

«Просрочено» = период предыдущего месяца (или раньше) в статусе draft/pending_review, не closed. Подсветить красным.

### Блок 4 — Динамика (сравнение с прошлыми месяцами)

**График:** линейная диаграмма по последним 6 месяцам (или сколько есть данных):
- Линия «Отработано часов» по месяцам
- Линия «ФОТ» по месяцам (вторая ось Y, т.к. другой масштаб)
- Опционально линия «Переработка»

Для admin — по всей компании. Для manager — по своему отделу.

**Важно:** если данных только за 1-2 месяца — график всё равно рисуется, просто с малым числом точек. Не падать на пустых данных. Если данных совсем нет — показать «Недостаточно данных для динамики, накопится со временем».

## Что нужно сделать

### Бэкенд

1. Создать сервис агрегации для дашборда. Он считает:
   - Сводку часов за месяц (всего, норма, переработка) — по компании или по отделу
   - Сводку ФОТ за месяц — общий, по отделам, по компаниям
   - Статусы периодов — список с состояниями, выявление просроченных
   - Динамику — массив помесячных агрегатов за последние N месяцев

2. Эндпойнты (с учётом ролей и фильтрации):
   - Сводка часов и ФОТ за месяц (admin/accountant — вся компания, manager — свой отдел)
   - Статусы периодов
   - Динамика по месяцам
   - Можно сделать один комбинированный эндпойнт `/api/dashboard/{year}/{month}` который отдаёт всё нужное для роли, или несколько мелких — на твой выбор как чище

3. Принудительная фильтрация по ролям на бэке:
   - manager получает только данные своего department_id
   - employee — только свои часы, без ФОТ
   - admin/accountant — всё

4. Переиспользуй существующий сервис расчёта ЗП (не дублируй формулы). Дашборд агрегирует то что уже считается для табеля.

5. Тесты: агрегация считается правильно, роли получают правильную видимость (manager не видит чужие отделы, employee не видит ФОТ).

### Фронтенд

1. Переделать страницу Дашборд (`DashboardPage` или аналог) — наполнить реальными данными.

2. Использовать recharts для графиков:
   - BarChart для часов по отделам и ФОТ по отделам/компаниям
   - LineChart для динамики
   - Карточки KPI сверху — простые компоненты с числом и подписью

3. Переключатель месяца сверху (как в табеле).

4. Кликабельные карточки/строки отделов → навигация в табель с предзаполненным фильтром (year, month, department_id).

5. Рендер по роли:
   - admin: все 4 блока, вся компания
   - accountant: блок статусов (главный) + ФОТ, без детального почасового по отделам если не нужно
   - manager: все блоки но только свой отдел
   - employee: простой персональный виджет (свои часы, норма, без денег)

6. Состояния загрузки и пустых данных (особенно для динамики).

7. Цвета — консистентные с легендой компаний/статусов в табеле (если есть общая палитра — переиспользовать).

## Что НЕ делать

- Не делать экспорт дашборда (PDF/Excel) — это отдельно если попросят
- Не делать настраиваемые виджеты (drag&drop) — фиксированный layout
- Не делать реалтайм-обновление — данные подгружаются при открытии и смене месяца
- Не делать прогнозы/предсказания — только фактические данные
- Не трогать табель, workflow, расчёт ЗП (только переиспользовать)

## Acceptance criteria

1. **Под admin**: дашборд показывает 4 блока — часы по отделам (столбцы), ФОТ по отделам и компаниям, статусы периодов, динамику по месяцам. Все отделы.

2. **Под manager**: те же блоки, но только свой отдел. Чужих отделов не видно.

3. **Под accountant**: акцент на статусах периодов (контроль закрытия) + ФОТ. Видит все отделы.

4. **Под employee**: простой виджет своих часов, без ФОТ и чужих данных.

5. **Клик по карточке/строке отдела** → переход в табель этого отдела за текущий месяц.

6. **Переключение месяца** обновляет все данные.

7. **Динамика**: если данных мало — график не падает, показывает что есть. Если нет — понятное сообщение.

8. `pytest -v` — всё зелёное, включая тесты ролевой видимости дашборда.

## Подводные камни

- **Производительность**: агрегация ФОТ по всем сотрудникам за месяц может быть тяжёлой если считать наивно. Если медленно — оптимизируй запросы, но не усложняй преждевременно.
- **Пустые данные**: новый отдел без сотрудников, месяц без часов, отсутствие истории для динамики — всё должно отрисовываться без ошибок.
- **Роли на бэке**: не доверяй фронту фильтрацию. manager не должен получить данные чужого отдела даже если подделает запрос.
- **Переиспользование расчёта ЗП**: дашборд должен показывать ТЕ ЖЕ цифры что табель и страница расчёта. Если будут расхождения — значит дублируется логика, унифицируй.
- **recharts и responsive**: графики должны вписываться в ширину контейнера, использовать ResponsiveContainer.
