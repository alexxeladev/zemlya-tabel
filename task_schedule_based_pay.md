# Задача — Оплата выходных/праздничных от ГРАФИКА сотрудника (не от календаря)

## Контекст

Сейчас оплата «праздничных/выходных» часов завязана на производственный календарь: часы в дни типа holiday/weekend оплачиваются по коэффициенту/фикс-ставке. Это НЕВЕРНО для сотрудников с графиками (особенно сменных).

**Правильная логика:** точка отсчёта — ГРАФИК сотрудника, не календарь.
- Работа в **рабочий день по графику** → по окладу (×1), даже если это календарный праздник
- Работа в **выходной по графику** (сотрудник вышел в свой законный выходной) → ×1,5 (или фикс-ставка)
- Переработка сверх дневной смены в рабочий день → отдельная категория (коэффициент переработки), НЕ меняется

Задача намеренно НЕ указывает имена конкретных функций, переменных, файлов. Разберись в коде сам (`app/services/payroll.py` — там сейчас логика holiday_hours через календарь). Действуй по правилу 3 попыток.


## Три категории оплаты (новое определение)

Для каждого дня определяем — рабочий он по ГРАФИКУ сотрудника или выходной по графику:

### 1. Оклад (обычная работа)
- День **рабочий по графику** → часы в пределах дневной нормы смены оплачиваются окладом
- Календарный праздник, попавший на рабочий день графика — всё равно по окладу (НЕ ×1,5)
- `base = rate × min(1, зачётные_рабочие_часы / норма)`

### 2. Переработка (сверх смены в рабочий день)
- В **рабочий день по графику** отработано больше дневной нормы смены → превышение = переработка
- Оплата: `overtime_hours × (rate/norm) × overtime_coefficient` (как сейчас)
- Не меняется, кроме того что «рабочий день» теперь определяется графиком

### 3. Выход вне графика (в выходной по графику) — бывшие «праздничные/выходные»
- День **выходной по графику** сотрудника, но он вышел (есть часы) → ВСЕ эти часы идут в категорию «вне графика»
- Оплата per-employee (как сейчас настроено): `weekend_pay_type=coefficient` → `часы × (rate/norm) × коэффициент` (дефолт 1.5); `fixed_rate` → `часы × фикс_ставка` (740₽)
- Это заменяет текущую логику «holiday_hours по календарю»

## Ключевое изменение

Сейчас: «выходной/праздничный» = день типа holiday/weekend в производственном календаре.
Стало: «выходной» = день, который НЕ является рабочим по ГРАФИКУ сотрудника.

Определение «рабочий день по графику»:
- **weekday-график** (5/2, 6/1, вс-чт): рабочий если день недели входит в рабочие дни графика. (Календарный праздник в рабочий день недели — спорный момент, см. ниже.)
- **cyclic-график** (2/2, 3/3): рабочий если по циклу от стартовой даты это рабочая смена. Календарь не влияет.

### Важный нюанс — праздники для weekday-графиков

Для 5/2: 12 июня (праздник) выпадает на рабочий день недели (например пятницу). По новой логике — это рабочий день ГРАФИКА → если сотрудник работал, оплата по окладу (×1).

НО: раньше система считала это «праздничным» (×1.5). Теперь — по окладу. Это соответствует уточнению пользователя: «праздничные и выходные у тех кто работает в графике считаются по окладу».

То есть: **работа в календарный праздник, попавший на рабочий день графика — оплачивается по окладу.** ×1.5 только за выход в СВОЙ ВЫХОДНОЙ (по графику).

Уточнение по норме: если 12 июня праздник и сотрудник НЕ работал (обычный отдых в праздник) — влияет ли на норму? Норма считается по графику. Для weekday с учётом календаря — праздник уменьшает норму (нерабочий). Оставь текущую логику расчёта нормы (она отдельно), меняется только оплата ОТРАБОТАННЫХ часов.
