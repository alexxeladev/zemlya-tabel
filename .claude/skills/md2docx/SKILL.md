## Документы в Word: `scripts/md2docx.py`

Документы для внешних читателей (ТЗ подрядчикам) лежат в `docs/` **парой**:
`.md` — источник правды, `.docx` — то, что отдают заказчику и 1С-подрядчику.

> Скрипт `scripts/md2docx.py` в git НЕ лежит (`scripts/` в `.gitignore`) — он есть
> только на этой машине. Нет файла — сказать пользователю, а не писать конвертер заново.

```bash
backend/.venv/bin/pip install python-docx     # разово: в зависимости проекта НЕ входит
python scripts/md2docx.py docs/TZ_1C_integration.md docs/TZ_1C_integration.docx
```

- **Правим только `.md` и перегенерируем `.docx`.** Ручная правка в Word теряется
  при следующей генерации. Перед правкой стоит убедиться, что `.docx` не редактировали
  мимо скрипта (сверить заголовки и число таблиц).
- Конвертер держит: заголовки **стилями** Word (работают навигация и оглавление),
  настоящие таблицы с повторяющейся шапкой и заливкой, блоки кода моноширинным,
  цитаты `>` — врезками с жёлтой заливкой и полосой слева, списки, инлайн
  `**bold**` / `*italic*` / `` `code` ``.
- **Оглавление** вставляется полем TOC на месте ПЕРВОЙ `---` (она считается концом
  титульного блока) и обновляется при открытии файла — в документе без `---`
  оглавления не будет.
- Поля страницы 1,6 см и шрифт таблиц 8,5 пт подобраны так, чтобы 7-колоночные
  таблицы ТЗ влезали в портретную A4. Уменьшать поля дальше — рассыпается печать.
- Markdown разбирается **своим** парсером (pandoc в окружении нет): подмножество
  синтаксиса, вложенные таблицы и HTML внутри `.md` не поддерживаются.
- Проверка результата после генерации — числом таблиц и заголовков против
  исходника (`grep -cE '^\|[ :-]+\|'` и `grep -cE '^#'`), иначе съехавшая разметка
  таблицы молча превратится в абзац текста.

Текущие документы: `docs/TZ_1C_integration.md` + `.docx` — ТЗ на интеграцию с
1С:ЗУП (актуальная версия). Лежащий рядом `docs/tz_1c_integration.md` (строчными) —
**устаревшая версия 1.0**, написана до позиций/совместительства, ночных смен,
отсутствий и трёх типов оплаты; на неё не опираться.
