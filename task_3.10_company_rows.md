# Задача 3.10 — Табель: строки по компаниям с финансами и кнопкой добавления

## Контекст

По обратной связи пользователей переделываем отображение табеля: каждый сотрудник показывается **несколькими строками — по числу компаний** на которых он работал. В каждой строке компании — финансовые показатели этой компании. Общие данные сотрудника объединены (merge). Дополнительные компании добавляются кнопкой «+» как сейчас добавляются слоты в днях.

Структура подтверждена с пользователем (диаграмма). Ниже — точное описание.

Задача намеренно НЕ указывает имена конкретных функций, переменных, файлов. Сначала разберись в текущем коде (как сейчас устроен табель, расчёт ЗП, отдача данных), потом реализуй. Действуй по правилу 3 попыток — если упёрся, остановись и спроси.

Перед началом — бэкап БД:
```bash
mkdir -p ~/backups
docker exec -t $(docker ps -q -f ancestor=postgres:16) pg_dump -U tabel tabel > ~/backups/before_3_10_$(date +%s).sql
```

## Структура таблицы

### Колонки слева направо

| Колонка | Уровень | Поведение |
|---|---|---|
| ФИО | сотрудник | merge (объединена) по всем строкам сотрудника |
| Отдел | сотрудник | merge |
| График | сотрудник | merge |
| Компания | компания | название/код компании этой строки + кнопки управления |
| дни 1…31 | компания | часы по ЭТОЙ компании в каждый день (слоты как сейчас) |
| Итого Ч по компании | компания | сумма часов сотрудника по этой компании |
| Оклад по компании | компания | доля оклада пропорционально часам компании |
| Сверхур. Ч по компании | компания | часы переработки по этой компании |
| Праздн. Ч по компании | компания | праздничные часы по этой компании |
| Сверхур. ₽ по компании | компания | оплата переработки по этой компании |
| Праздн. ₽ по компании | компания | оплата праздничных по этой компании |
| Итого Ч | сотрудник | merge — сумма всех часов сотрудника по всем компаниям |
| Итого ₽ | сотрудник | merge — вся выплата сотруднику |
| Δ (дельта) | сотрудник | merge — отработано минус норма |
| Норма | сотрудник | merge — месячная норма часов. ТОЛЬКО ЗДЕСЬ (не дублировать слева) |

### Merge (объединение ячеек)

Колонки уровня «сотрудник» (ФИО, Отдел, График, Итого Ч, Итого ₽, Δ, Норма) — заполнены в ПЕРВОЙ строке сотрудника и визуально растянуты (rowspan) на все его строки-компании. В остальных строках сотрудника эти колонки пустые (под объединённой ячейкой).

## Строки компаний: поведение

### По умолчанию — одна строка

При открытии табеля у каждого сотрудника показывается **одна строка — его родительская (основная) компания** (поле default_company сотрудника). Если у сотрудника уже есть часы на других компаниях за этот период — те строки тоже показываются автоматически (данные есть → показываем).

### Кнопка «+ комп.» — добавление строки

В колонке «Компания», под существующими строками компаний сотрудника — кнопка «+ комп.» (пунктирная, небольшая, в стиле кнопки добавления слота в днях).

- Клик → выпадающий список компаний которые ещё не добавлены этому сотруднику
- Выбор → появляется новая строка-компания, можно вводить часы по дням
- Доступно только в статусе периода draft (если период не draft — кнопки нет)

### Кнопка «×» — удаление строки

На дополнительной строке-компании (не родительской) — кнопка «×» рядом с названием компании.

- Доступна **только если в этой строке 0 часов** за весь период
- Клик → строка убирается
- Доступно только в draft

### Родительская компания — нельзя удалить

Строка родительской (основной) компании сотрудника:
- Показывается всегда
- Помечена визуально (например «осн.» или иконка/цвет)
- Кнопки «×» у неё нет — удалить нельзя

## Финансы по компаниям

Распределение по принципу доли часов:
- `доля_компании = часы_компании / всего_часов_сотрудника`
- `оклад_компании = общий_оклад × доля`
- Сверхурочные часы/деньги по компании — пропорционально (или точнее, если переработка конкретного дня привязана к компании где были часы; пропорциональный подход тоже приемлем)
- Праздничные часы/деньги по компании — аналогично

Округление денег — Decimal, ROUND_HALF_EVEN. Сумма по компаниям может отличаться от общего итога на 1-2₽ из-за округления; общий «Итого ₽» берётся как сумма по компаниям чтобы визуально сходилось.

## ВАЖНО — переключатель версий (старый вид / новый вид)

Новый вид табеля (строки по компаниям) делается **рядом** со старым, не вместо. Это для тестирования и показа пользователям — чтобы можно было сравнить и собрать обратную связь, прежде чем окончательно перейти.

Требования:

1. **Старый компонент табеля НЕ удалять и НЕ ломать.** Он остаётся рабочим как есть. Новый вид — отдельный компонент/режим рендеринга.

2. **Переключатель в шапке страницы табеля**: тумблер или две кнопки «Классический вид / По компаниям». Переключает между старым и новым отображением мгновенно, без перезагрузки.

3. **Выбор запоминается** — чтобы при переключении месяца или возврате на страницу вид не сбрасывался. Хранить в state приложения (zustand store) или в user preferences. НЕ в localStorage (он не работает в этом окружении надёжно — используй state).

4. Оба вида используют ОДНИ И ТЕ ЖЕ данные с бэка — отличается только рендеринг. Бэкенд отдаёт всё что нужно для обоих.

5. По умолчанию при первом заходе — можно оставить старый вид (классический), чтобы ничего внезапно не поменялось для текущих пользователей. Новый включается тумблером.

Когда пользователи протестируют и выберут — в отдельной будущей задаче удалим проигравший вариант. Сейчас держим оба.

## Что нужно сделать

### Бэкенд

1. Отдача данных табеля должна позволять фронту построить разбивку по компаниям с финансами каждой компании + общие итоги. Если расчёт ЗП уже даёт breakdown по компаниям — переиспользовать. Если нет — добавить в результат расчёта разбивку по компаниям (часы, оклад, сверхур. Ч/₽, праздн. Ч/₽ на каждую компанию).

2. Список доступных компаний для добавления (которые ещё не у сотрудника) — фронт может вычислить сам из общего списка компаний минус уже показанные. Отдельный эндпойнт не обязателен.

3. Excel-генерация — переделать на строки по компаниям (часовые колонки).

4. Тесты: разбивка по компаниям считается правильно, суммы сходятся (часы по компаниям = итого часов, оклады по компаниям ≈ общий оклад).

### Фронтенд

1. Переделать рендеринг таблицы табеля: каждый сотрудник = N строк по компаниям. Merge общих колонок через rowspan.

2. Кнопка «+ комп.» в колонке «Компания» под строками сотрудника (только draft). Выпадающий список оставшихся компаний.

3. Кнопка «×» на дополнительных строках (только при 0 часов, только draft).

4. Родительская компания помечена, без «×».

5. Финансовые колонки по компании (Оклад, Сверхур. Ч/₽, Праздн. Ч/₽) — видны admin/accountant/manager (как сейчас финансы). Employee их не видит (для employee показываются только часовые: дни, Итого Ч по компании, общий Итого Ч; без денег).

6. Общие колонки (Итого Ч, Итого ₽, Δ, Норма) в первой строке сотрудника, merge.

7. Сохранить работающий скролл и sticky (левые колонки ФИО/Отдел/График — sticky слева, шапка sticky сверху). Не сломать то что уже работает.

## Acceptance criteria

0. **Переключатель**: в шапке табеля тумблер «Классический вид / По компаниям». Переключает мгновенно. Выбор сохраняется при смене месяца. Старый вид работает как раньше, новый — строки по компаниям.

1. **Табель (новый вид)**: сотрудник по умолчанию — одна строка (родительская компания). Кнопка «+ комп.» добавляет строку другой компании. «×» убирает дополнительную (если 0 часов). Родительскую убрать нельзя.

2. **Финансы по компании**: в каждой строке компании — Итого Ч, оклад, сверхур. Ч/₽, праздн. Ч/₽ этой компании. Суммы сходятся с общим итогом.

3. **Общие итоги**: Итого Ч, Итого ₽, Δ, Норма — объединены (merge) в первой строке сотрудника. Норма только справа.

4. **Excel**: строки по компаниям, только часовые колонки (без рублей).

5. **Роли**: employee не видит финансовых колонок по компаниям. Manager/accountant/admin видят.

7. `pytest -v` зелёный.

## Подводные камни

- **rowspan и sticky одновременно** — это самая сложная часть вёрстки. Merge-ячейки (rowspan) в sticky-колонках могут вести себя капризно. Если возникнут проблемы — опиши где именно, не ломай существующий скролл.
- **Суммы должны сходиться** — часы по компаниям = Итого Ч. Если из-за округления оклады по компаниям не дают точно общий оклад, общий берётся как сумма частей.
- **default_company может быть null** — если у сотрудника нет основной компании, первая строка — любая компания где есть часы, либо пустая строка-плейсхолдер с кнопкой «+ комп.».
- **Период не-draft** — кнопки «+ комп.» и «×» скрыты, строки только просмотр.
