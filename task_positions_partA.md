# Задача — Совместительство (Часть A): модель позиций + расчёт (бэкенд)

## Контекст

Сотрудник может занимать несколько должностей (совместительство) — основную + дополнительные. У каждой должности (позиции) свой оклад, график, отдел, компания, коэффициент выходных, тип оплаты и свой учёт времени. Расчёт по каждой позиции отдельно.

Это **Часть A — бэкенд и расчётная модель**. UI табеля (строки по позициям, ввод времени) — Часть B, отдельно и позже.

**КРИТИЧЕСКИ ВАЖНО:** это изменение ядра модели. Сотрудник с ОДНОЙ позицией должен работать ТОЧНО как сейчас. Миграция создаёт каждому текущему сотруднику одну основную позицию из его данных — ничего не должно сломаться.

Задача намеренно НЕ указывает имена конкретных функций, переменных, файлов. Разберись в коде сам (модель Employee, расчёт payroll, все места где берётся оклад/график/отдел/компания сотрудника). Действуй по правилу 3 попыток.

## Модель

### Позиция (новая сущность)

Сотрудник имеет 1+ позиций. Позиция — «рабочее место»:
- Ссылка на сотрудника
- Должность (название)
- Тип оплаты и соответствующая база — ОДИН из трёх: **окладная** (месячный оклад), **посменная** (ставка за смену), **почасовая** (ставка за час). См. раздел «Три типа оплаты» ниже.
- График
- Отдел
- Компания (основная компания позиции)
- Коэффициент/тип оплаты выходных (коэффициент или фикс-ставка)
- Коэффициент переработки (0 / 1 / 1.5) — применяется к часам сверх нормы
- Ночные смены (флаг + ставка, если применимо к позиции)
- Признак «основная» (одна позиция основная, остальные — совместительство)

### Три типа оплаты позиции

У позиции — один из трёх типов, определяющий расчёт базы:

1. **Окладная**: есть месячный оклад. База = оклад / норма × отработанные часы (cap на оклад при полной отработке). Гарантированный оклад при отработке нормы. (Как сейчас.)

2. **Посменная**: нет оклада, есть ставка за смену. База = число смен × ставка. Отсутствия (отпуск/больничный) от условного оклада = ставка × норма смен месяца. (Уже заложено ранее.)

3. **Почасовая** (НОВОЕ): нет оклада, есть **ставка за час**. 
   - База = отработанные_часы_в_пределах_нормы × ставка_за_час
   - Переработка = max(0, факт_часов − норма_месяца) × ставка_за_час × коэффициент_переработки (0/1/1.5 из карточки позиции)
   - Норма — от графика/календаря позиции (норма часов месяца)
   - **Отпуск/больничный НЕ начисляются** почасовику (в отличие от посменной). Если почасовик в отпуске/болезни — за эти дни просто нет часов (0 оплаты), код отсутствия отмечается справочно.
   - Премии/KPI/удержания/распределение — как у всех, от «итого начислено»
   - Отличие от окладной: у окладника гарантированный оклад (отработал норму → полный оклад); у почасовика только за фактические часы (отработал меньше нормы → пропорционально меньше)

### Что переезжает с сотрудника на позицию

Сейчас на сотруднике (Employee): оклад, график, отдел, компания, коэффициент выходных, тип оплаты, ночные. ВСЁ ЭТО переезжает на позицию.

### Что остаётся на сотруднике (человеке)

- ФИО, табельный номер, доступ (email/роль/пароль), managed_departments (если manager)
- Премии, KPI, займ, аванс — на человека, НО с привязкой к конкретной позиции (см. ниже)

### Премии/KPI/удержания и позиции

- Премия, KPI, займ, аванс — начисляются человеку, но при создании **выбирается позиция** к которой они относятся (по умолчанию — основная)
- Они попадают в «к выплате» той позиции
- Модель: у премии/удержания/займа — ссылка на позицию (не только на сотрудника)

## Миграция (защита от поломок)

1. Создать таблицу позиций
2. Для КАЖДОГО существующего сотрудника — создать ОДНУ позицию с признаком «основная», перенеся в неё его текущие оклад/график/отдел/компанию/коэффициент/тип оплаты/ночные
3. Существующие премии/займы/удержания — привязать к этой основной позиции
4. Существующие записи табеля (часы) — привязать к основной позиции
5. Проверить: после миграции всё считается ТАК ЖЕ как до неё (та же зарплата у всех)
6. alembic upgrade head + alembic current = head

## Расчёт

- Расчёт ЗП идёт **по каждой позиции отдельно**: оклад/переработка/выходные/отсутствия — по данным позиции (её оклад, график, коэффициент)
- Переработка — по графику позиции (по дням, как сейчас)
- Выходные/праздничные — по графику позиции (от графика, не календаря)
- Отсутствия — по позиции (у каждой свой график и норма)
- **К выплате по позиции** = начислено позиции + премии/KPI этой позиции − удержания этой позиции
- «К выплате» НЕ суммируется между позициями (разные компании платят отдельно) — но общий итог по человеку можно показывать справочно
- Распределение по компаниям — по каждой позиции от её данных (у позиции своя компания и своё распределение)

### Норма и время

- У каждой позиции своя норма (по её графику)
- Время (часы/смены) учитывается по позиции (в Части B будет ввод; в Части A — модель хранит время с привязкой к позиции)

## Что НЕ делать в Части A

- НЕ делать UI табеля со строками по позициям — это Часть B
- НЕ делать вахту
- Не ломать существующее поведение (сотрудник с 1 позицией = как раньше)
- Не рефакторить сверх задачи

## Acceptance criteria

1. Модель позиций: сотрудник имеет 1+ позиций, каждая со своим окладом/графиком/отделом/компанией/коэффициентом/типом оплаты.
2. Миграция: каждому существующему сотруднику создана 1 основная позиция из его данных. Зарплаты после миграции идентичны тем что были.
3. Расчёт по каждой позиции отдельно (оклад, переработка, выходные, отсутствия — по данным позиции).
4. **Три типа оплаты работают**: окладная (оклад/норма×часы), посменная (смены×ставка), почасовая (часы×ставка/час, переработка сверх нормы по коэффициенту, отпуск/больничный не начисляются).
5. Премии/KPI/займ/аванс — с привязкой к позиции, попадают в к выплате той позиции.
6. К выплате по позиции (не суммируется), распределение по компаниям от данных позиции.
7. Сотрудник с ОДНОЙ позицией считается точно как раньше (регрессия не сломана).
8. `pytest -v` зелёный, включая: расчёт по позиции, миграция сохраняет суммы, одна позиция = старое поведение, премия к позиции, две позиции с разными окладами, почасовой расчёт (часы×ставка + переработка).

## Подводные камни

- **ВСЕ места где берётся оклад/график/отдел/компания сотрудника** — теперь через позицию. Найди все, не пропусти. Это самое опасное — пропущенное место сломает расчёт.
- **Обратная совместимость** — сотрудник с одной позицией должен вести себя идентично. Прогони тесты ДО и убедись что суммы не поехали.
- **Миграция данных** — существующие часы/премии/займы привязать к основной позиции, иначе потеряются.
- **Основная позиция** — ровно одна на сотрудника, признак. При создании сотрудника — создаётся основная позиция.
- **Distribution/ведомость/дашборд** — они агрегируют по сотрудникам; теперь агрегируют по позициям. Проверь что не сломались (в Части A — расчётная часть; полный UI в Части B).
- Decimal, миграции.
