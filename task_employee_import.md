# Задача — Импорт сотрудников из Excel (шаблон + превью)

## Контекст

В админке нужен загрузчик сотрудников из Excel, чтобы не вводить 300+ человек вручную. Скачиваемый шаблон + умное распознавание значений + превью перед импортом.

Задача намеренно НЕ указывает имена конкретных функций, переменных, файлов. Разберись в коде сам (модель Employee, справочники компаний/отделов/графиков, CRUD сотрудников). Действуй по правилу 3 попыток.

Перед началом — бэкап БД:
```bash
mkdir -p ~/backups
docker exec -t $(docker ps -q -f ancestor=postgres:16) pg_dump -U tabel tabel > ~/backups/before_import_$(date +%s).sql
```

## Процесс импорта (3 шага)

1. **Скачать шаблон** — кнопка «Скачать шаблон Excel» в админке (раздел Сотрудники). Отдаёт .xlsx с фиксированными колонками и примером-подсказкой в первой строке данных.
2. **Загрузить заполненный** — кнопка «Импорт из Excel», выбрать файл.
3. **Превью + подтверждение** — система парсит, показывает таблицу превью: что распозналось, какие строки с ошибками (подсвечены), сводка «Готово к импорту: N, с ошибками: M». Кнопки «Импортировать N валидных» / «Отмена». Импорт происходит ТОЛЬКО после подтверждения.

## Шаблон — колонки

| Колонка | Обязательна | Примечание |
|---|---|---|
| Табельный номер | нет | если пусто — оставить пустым |
| ФИО | ДА | полное ФИО |
| Компания (основная) | ДА | должна существовать в справочнике |
| Отдел | нет | если пусто — «Без отдела»; если указан — должен существовать |
| Должность | нет | текст |
| График | нет | должен существовать в справочнике (5/2, 2/2 и т.д.) |
| Тип оплаты | нет | «окладная» / «посменная», по умолчанию окладная |
| Оклад | зависит | для окладной; число |
| Ставка за смену | зависит | для посменной; число |
| Оплата выходных | нет | «коэффициент» / «фикс», по умолчанию коэффициент |
| Коэффициент / ставка выходных | нет | число (1.5 или 740) |
| Дата приёма | нет | дата |

Первая строка листа — заголовки, вторая — пример (серым, подсказка формата), с третьей — данные. При парсинге пример-строку пропускать (пометить явно, например «ПРИМЕР — удалите эту строку»).

## Умное распознавание значений

При парсинге нормализовать:
- **График**: `5\2`, `5 / 2`, ` 5/2 ` → `5/2`. Искать соответствие в справточнике графиков по нормализованному имени (регистронезависимо, без лишних пробелов/слешей). Если не найден — ошибка строки.
- **Компания**: убрать кавычки (`ООО "Комфорт"` → сопоставить с `Комфорт` или полным именем в справочнике), лишние пробелы. Искать по коду или имени.
- **Отдел**: пробелы, регистр.
- **Тип оплаты**: «окладная»/«оклад»/«salary» → окладная; «посменная»/«смена»/«за смену» → посменная. Гибко.
- **Оплата выходных**: «коэффициент»/«коэф»/«×1.5» → коэффициент; «фикс»/«фиксированная»/«740» → фикс.
- **Числа**: оклад/ставка — принять с пробелами-разделителями («50 000»), запятой/точкой.
- **Даты**: разные форматы (ДД.ММ.ГГГГ, Excel-дата).

## Валидация (в превью)

Для каждой строки проверить и показать статус:
- **Валидна** — все обязательные поля есть, справочные значения найдены
- **Ошибка** — с указанием ЧТО не так:
  - Нет ФИО → «ФИО обязательно»
  - Компания не найдена в справочнике → «Компания 'X' не найдена»
  - Отдел указан но не найден → «Отдел 'X' не найден»
  - График указан но не найден → «График 'X' не найден»
  - Окладная без оклада / посменная без ставки → «Не указан оклад/ставка»
  - Дубль табельного номера (в файле или с существующим в БД) → «Таб.№ 'X' уже существует»
  - Оклад/ставка не число → «Оклад не число»

В превью — таблица со всеми строками, ошибочные подсвечены красным с текстом ошибки. Сводка сверху.

## Импорт

- Импортируются ТОЛЬКО валидные строки (частичный импорт валидных, ошибочные пропускаются — пользователь видел их в превью и согласился)
- Каждая строка → создание сотрудника через существующую логику (не в обход валидации моделей)
- Доступы (email/роль/пароль) НЕ импортируются — только справочные данные
- После импорта — отчёт: «Создано N сотрудников. Пропущено M (ошибки)».

## Дубли

- Дубль по табельному номеру — ошибка (не создавать второго с тем же таб.№, если таб.№ используется как идентификатор)
- Если таб.№ пустой — дубль определять по ФИО? Осторожно: полные тёзки возможны. Предложи: при пустом таб.№ дубль по ФИО — предупреждение (не блок), пользователь решает. Или просто создавать (не проверять дубль по ФИО). Уточни у меня если критично — по умолчанию: дубль проверяем только по непустому таб.№.

## Модель / API

- Эндпойнты: скачать шаблон (GET, отдаёт xlsx), превью (POST файл → распарсенные строки со статусами, БЕЗ создания), импорт (POST подтверждённые данные → создать). Или превью+импорт одним потоком с флагом confirm. На твой выбор что чище.
- Доступ: только admin.
- Парсинг через openpyxl.
- Миграций скорее всего не требуется (используем существующую модель Employee). Если нужны — применить.

## Что НЕ делать

- НЕ импортировать доступы (email/роль/пароль)
- НЕ импортировать часы табеля, премии, займы — только карточку сотрудника
- НЕ создавать справочники автоматически (компании/отделы/графики должны существовать; если нет — ошибка строки). Хотя можешь предложить в превью «создать отдел X?» — но по умолчанию просто ошибка.
- Не рефакторить сверх задачи

## Acceptance criteria

1. Кнопка «Скачать шаблон» отдаёт xlsx с колонками и примером.
2. Кнопка «Импорт», выбор файла → превью со статусами строк.
3. Умное распознавание: `5\2`→`5/2`, компания в кавычках сопоставляется, «50 000» → число.
4. Ошибочные строки подсвечены с текстом ошибки, сводка сверху.
5. Импорт только после подтверждения, только валидные строки.
6. Дубль таб.№ — ошибка.
7. Посменные и окладные оба импортируются корректно.
8. Только admin.
9. После импорта — отчёт создано/пропущено.
10. `pytest -v` зелёный, тесты: парсинг нормализации, валидация каждого типа ошибки, дубль таб.№, частичный импорт, посменная/окладная.

## Подводные камни

- **Пример-строка** в шаблоне — не импортировать её. Пометить явно.
- **Сопоставление справочников** — по нормализованному имени/коду. Собери справочники один раз в память, сопоставляй.
- **openpyxl даты** — Excel хранит даты по-своему, обработать.
- **Числа с пробелами** — «50 000» это 50000 (неразрывный пробел тоже).
- **Транзакция** — импорт валидных лучше в одной транзакции (или батчами), чтобы при сбое не создать половину. Но частичный импорт (валидные создаются, ошибочные нет) — это ОК, ошибочные уже отфильтрованы в превью.
- **Большой файл (300+ строк)** — превью не должно вешать интерфейс, парсинг за разумное время.
- **Кодировка/спецсимволы** в ФИО (ё, дефисы) — сохранять как есть.
