# Задача 3.11 (Б) — Раздел «Расчёт ЗП»: сводная ведомость + распределение по компаниям в %

## Контекст

В системе есть табель с расчётом зарплаты, премиями, KPI, удержаниями (займ, аванс) и расчётом «К выплате». Теперь нужен раздел «Расчёт ЗП» — сводная ведомость по всем сотрудникам с возможностью распределения затрат между юрлицами (компаниями) в процентах, и выгрузкой в Excel.

Задача намеренно НЕ указывает имена конкретных функций, переменных, файлов. Сначала разберись в текущем коде (расчёт ЗП, премии/удержания, справочник компаний, существующая страница расчёта ЗП если есть), потом реализуй. Действуй по правилу 3 попыток.

## ПУНКТ 0 (ВАЖНО) — Вернуть расчёт переработки на ПО МЕСЯЦУ

По уточнению финдиректора расчёт переработки меняется обратно на **помесячный** (раньше делали по дням).

**Новая (правильная) логика переработки:**
- `переработка_часов = ФАКТ_часов_за_месяц − НОРМА_часов_месяца` (если положительно, иначе 0)
- `сумма_переработки = (оклад / норма_месяца) × переработка_часов × коэффициент`
- где коэффициент — это N из карточки сотрудника (0 / 1 / 1.5)

То есть НЕ по каждому дню, а от месячного итога. Это соответствует образцу ведомости финдира (`O = M − L`, `P = I/L × O × N`).

Найди где сейчас считается переработка (вероятно по дням после прошлой задачи) и переделай на помесячную. Обнови тесты.

## ПУНКТ 1 — Распределение по компаниям в % (механизм)

Это управленческое распределение затрат на сотрудника между юрлицами. НЕ связано с часами в табеле — отдельный механизм.

### Модель данных

**Проценты по умолчанию — в карточке сотрудника:**
- Набор «компания → процент» для сотрудника
- Компании берутся из существующего справочника компаний (НЕ захардкожены)
- Сумма процентов должна давать 100% (валидация при сохранении; допустить 99-101 из-за округления, либо нормализовать)
- Пример: кладовщик — Комфорт 50%, ЗМО 30%, ГХС 20%

**Переопределение на период (гибрид):**
- При формировании ведомости за месяц проценты подставляются из карточки по умолчанию
- Бухгалтер/финконтролёр может скорректировать проценты на КОНКРЕТНЫЙ месяц прямо в ведомости
- Правка сохраняется для этого периода, НЕ меняя умолчание в карточке
- Это та же логика что у займа (дефолт + ручная правка за месяц) — сделай единообразно

**Таблицы:**
- Проценты по умолчанию: привязка employee + company + percent (в карточке)
- Помесячное переопределение: employee + company + year + month + percent (создаётся при правке в ведомости)
- При расчёте: если есть переопределение на месяц — берём его, иначе дефолт из карточки

### Расчёт распределения

- База распределения = **Итого начислено** (оклад + переработка + премии + KPI). ДО вычета удержаний. (ВАЖНО: финдир скорректировал — в образце было от «к выплате», но мы берём от Итого начислено)
- `сумма_компании = Итого_начислено × процент_компании`
- Сумма по всем компаниям = Итого начислено (с точностью округления)
- Округление Decimal ROUND_HALF_EVEN; расхождение в 1-2₽ относим на основную компанию или последнюю

## ПУНКТ 2 — Страница «Расчёт ЗП» (сводная ведомость)

Отдельная страница в приложении (пункт «Расчёт ЗП» в sidebar уже есть — наполнить/переделать).

### Структура таблицы (по образцу ведомости финдира, лист «Подразделение»)

Колонки:
1. № п/п
2. Табельный номер
3. ФИО
4. Компания (основная / источник выплаты)
5. Подразделение/Отдел
6. Должность
7. Режим работы (график)
8. Оклад
9. Норма час
10. Факт час
11. Коэф. переработки (0/1/1.5)
12. Кол-во переработки (факт − норма)
13. Сумма переработки
14. Начислено оклад
15. Премия базовая
16. KPI
17. Премия (доп.)
18. **Итого начислено** = оклад + переработка + премии + KPI
19. Аванс/Удержано (займ доля + аванс)
20. **К выплате** = Итого начислено − удержано
21. **Разбивка по %** — редактируемые ячейки процентов на месяц
22. Колонки по каждой компании из справочника — сумма = Итого начислено × %
23. Итого разбивка = сумма по компаниям (контроль = Итого начислено)
24. Примечание

(Колонки отпуск/больничный — J, K, R в образце — ПОКА НЕ делаем, отложены. Можно оставить пустые плейсхолдеры или не показывать.)

### Поведение

- Переключатель месяца (как в табеле)
- Строки — все сотрудники (для admin/accountant — все; manager — свой отдел)
- Проценты распределения — редактируемые прямо в таблице (правка на месяц)
- При изменении процента — пересчёт сумм по компаниям в реальном времени
- Подсветка если сумма процентов ≠ 100% (предупреждение)
- Итоговая строка снизу — суммы по всем числовым колонкам
- Доступ: admin, accountant — все; manager — свой отдел (read-only финансы своего отдела); employee — нет доступа к этой странице

## Что НЕ делать

- НЕ делать отпуска/больничные (колонки J, K, R) — отложено, плейсхолдеры или пропуск
- НЕ делать сменные графики, вахту
- НЕ делать компенсацию неиспользованного отпуска
- НЕ делать регламент исключений переработки (кому не платится) — пока коэффициент 0 в карточке закрывает это вручную
- Не трогать workflow периодов, ролевую модель табеля
- Не рефакторить сверх задачи

## Acceptance criteria

1. **Переработка по месяцу**: факт − месячная норма, сумма = оклад/норма × часы × коэф. Тест проверяет на примере.
2. **Проценты в карточке**: задаётся компания → %, сумма 100%, валидация.
3. **Переопределение на месяц**: в ведомости можно поправить % на конкретный период, не меняя карточку.
4. **Страница ведомости**: таблица по структуре образца, переключение месяца, редактируемые проценты, пересчёт сумм по компаниям, итоговая строка.
5. **Распределение от Итого начислено**: сумма_компании = Итого_начислено × %. Сумма по компаниям = Итого начислено.
6. **Excel**: выгрузка ведомости по образцу.
7. **Роли**: admin/accountant — все, manager — свой отдел, employee — нет доступа.
8. `pytest -v` зелёный, включая тесты переработки (месячной), распределения %, переопределения на период.

## Подводные камни

- **Изменение логики переработки** затронет существующие тесты и расчёты — обнови их. Убедись что цифры в табеле и ведомости совпадают (один источник расчёта).
- **Сумма процентов ≠ 100%** — решить как обрабатывать: предупреждение + всё равно посчитать, или блокировать. По умолчанию — предупреждать, но считать (нормализовать или как есть).
- **Decimal округление** при распределении — сумма частей должна сходиться с целым; расхождение относить на одну компанию.
- **Миграции** — новые таблицы (проценты дефолт, переопределение на период). После создания alembic upgrade head + проверка alembic current = head.
- **Производительность** — ведомость по всем 100+ сотрудникам со всеми расчётами может быть тяжёлой. Переиспользуй существующий расчёт ЗП, не дублируй.
- **Единый источник расчёта** — ведомость должна использовать ТОТ ЖЕ расчёт что табель. Если будут расхождения цифр — унифицируй.
