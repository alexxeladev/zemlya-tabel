# Задача — Раздел «ВАХТА» (Часть 1): базовый табель охраны

## Контекст

Отдельный раздел системы для учёта работы охраны вахтовым методом. Устроен иначе чем обычный табель: период — половина месяца, ввод ручной (факт выхода), оплата посменная от поста (объекта), состав охранников гибкий.

Это Часть 1 (базовый табель). Часть 2 (официальная выплата с балансом, выгрузка Excel) — ПОЗЖЕ, в этой задаче НЕ делаем.

**Зависимость:** опирается на мульти-отдел менеджеров (задача оргструктуры) — менеджер охраны может вести раздел. Если оргструктура уже сделана — переиспользуй managed_departments.

Задача намеренно НЕ указывает имена конкретных функций, переменных, файлов. Разберись в коде сам. Действуй по правилу 3 попыток.

## Концепция

Раздел «ВАХТА» — отдельный пункт в меню (рядом с Табель, Расчёт ЗП). Своя логика:
- **Период = половина месяца**: 1-15 и 16-31 (две ведомости в месяц)
- **Ввод ручной**: ответственный отмечает факт выхода охранника в день (галочка/смена), без графика-цикла и автозаполнения
- **Оплата посменная**: смены × ставка поста
- **Гибкий состав**: охранники добавляются/меняются между периодами

## ЧАСТЬ A — Справочник постов (объектов)

Плоский справочник постов. Пост = объект.

Поля поста:
- Название (например «GW 1», «SH - RIVER», «Стройгородок», «S7 AERO»)
- **Ставка за смену** (Decimal, одна на пост)
- **Распределение по компаниям** (%) — набор «компания → процент» для этого поста, сумма 100%. Переиспользуй механизм распределения (метод наибольшего остатка, кнопка «разнести поровну» если есть)

Управление справочником постов — admin (и, возможно, менеджер охраны). CRUD постов.

## ЧАСТЬ B — Модель табеля вахты

- **Период вахты**: год + месяц + половина (1=дни 1-15, 2=дни 16-конца месяца)
- **Строка охранника в периоде**: сотрудник + назначенный пост (по умолчанию на период) + ставка (от поста) + отметки выхода по дням
- **Отметка выхода**: факт выхода в конкретный день (смена). Просто «вышел/не вышел» (1/0 или галочка)
- **Смена поста внутри периода** (редкое исключение): возможность переопределить пост для конкретного дня/смены. По умолчанию — пост на весь период; если в какой-то день охранник на другом посту — переопределить этот день. Оплата и распределение этого дня — от переопределённого поста.

Создать миграцию, применить, alembic current = head.

## ЧАСТЬ C — Расчёт вахты

Для каждого охранника в периоде:
- **Кол-во смен** = число отмеченных выходов
- **Зарплата** = Σ по сменам (ставка поста этой смены). Обычно все смены на одном посту → смены × ставка. Если были переопределения — суммировать по фактическим постам.
- **Премия** — сумма (кнопкой +, как в основном табеле; обоснование опционально для вахты или как решим — по умолчанию можно без обоснования для простоты, но лучше с)
- **Штраф** — простое удержание (сумма вычитается, БЕЗ обоснования)
- **К выплате** = Зарплата + Премия − Штраф
- **Распределение по компаниям** — смены группируются по постам, каждая группа разносится по % своего поста; суммируется. То есть затраты на охранника разносятся по компаниям согласно тому на каких постах он стоял.

Все деньги Decimal, ROUND_HALF_EVEN. Округление распределения — метод наибольшего остатка (переиспользуй).

## ЧАСТЬ D — Интерфейс раздела «ВАХТА»

- Пункт меню «ВАХТА»
- Переключатель: месяц + половина (1-15 / 16-31)
- Таблица-ведомость охраны, колонки:
  № / ФИО / Должность / **Пост** / **Ставка** / дни половины месяца (с отметками выхода) / **Кол-во смен** / **Зарплата** / Премия / Штраф / **К выплате** / Примечание / разбивка по компаниям
- **Добавление охранника**: менеджер охраны может добавить сотрудника в ведомость вахты (выбрать из сотрудников или создать). Гибкий состав — в разных периодах разные люди.
- Назначение поста охраннику на период (выпадающий список постов) → ставка подтягивается
- Отметка выхода по дням (клик/галочка)
- Итоговая строка (сумма смен, зарплат, к выплате, по компаниям)

## ЧАСТЬ E — Роли и доступ

- **Менеджер охраны** (manager с доступом к отделу охраны через managed_departments) — ведёт раздел ВАХТА: заполняет табель, добавляет/меняет охранников, назначает посты, ставит премии/штрафы
- **admin, accountant** — видят раздел ВАХТА для контроля (просмотр, возможно правка)
- Employee — не видит раздел ВАХТА (или видит только свои смены, если он охранник — опционально, по умолчанию не видит)
- Принудительная проверка на бэке: раздел доступен только уполномоченным

- НЕ делать автозаполнение из банковских выписок — потом

## Acceptance criteria

1. Справочник постов: создание поста с названием, ставкой, распределением по компаниям (%).
2. Раздел «ВАХТА» в меню, переключение месяц + половина.
3. Менеджер охраны добавляет охранника в ведомость, назначает пост, отмечает выходы.
4. Зарплата = смены × ставка поста. Пример: 12 смен × 4000 = 48000.
5. Штраф вычитается, премия добавляется. К выплате = зарплата + премия − штраф.
6. Распределение по компаниям от % поста. Пример: пост Green Wood 50% ЗМО / 50% Комфорт → зарплата разносится пополам.
7. Смена поста внутри периода: день на другом посту считается по его ставке/%.
8. Гибкий состав: в периоде 1-15 одни охранники, 16-31 другие.
9. Роли: менеджер охраны ведёт, admin/accountant видят, employee нет.
10. `pytest -v` зелёный, тесты: расчёт смен, штраф/премия, распределение от поста, смена поста в периоде, доступ по ролям.

## Подводные камни

- **Период — половина месяца**, не весь месяц. Не путать с обычными периодами табеля (там месяц). Отдельная сущность периода вахты.
- **Пост несёт ставку и %** — охранник наследует от назначенного поста. Смена поста → другая ставка/%.
- **Распределение по постам** — если охранник на разных постах в периоде, разносить по фактическим постам смен.
- **Гибкий состав** — охранник в ведомости вахты не обязательно «сотрудник отдела» в обычном смысле; продумай как добавлять (существующий сотрудник или новый). По умолчанию — выбор из существующих сотрудников + возможность создать.
- **Мульти-отдел** — менеджер охраны через managed_departments. Если оргструктура не готова — заложи доступ через роль/отдел охраны, согласуй со мной.
- Decimal, миграции (alembic upgrade head + проверка).
