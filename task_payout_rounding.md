# Задача — Округление «К выплате» до 100₽ (вниз) + эффект округления на дашборде

## Контекст

Руководство просит округлять итоговую сумму «К выплате» каждого сотрудника до 100₽ вниз. При этом на дашборде нужно видеть суммарный эффект округления за период (сколько составили «хвосты»).

Задача намеренно НЕ указывает имена конкретных функций, переменных, файлов. Разберись в коде сам. Действуй по правилу 3 попыток.

Перед началом — бэкап БД:
```bash
mkdir -p ~/backups
docker exec -t $(docker ps -q -f ancestor=postgres:16) pg_dump -U tabel tabel > ~/backups/before_rounding_$(date +%s).sql
```

## Логика округления

- **К выплате** каждого сотрудника округляется **ВНИЗ до 100₽** (floor до сотни).
  - Пример: 110 407₽ → 110 400₽; 26 826₽ → 26 800₽; 153 659₽ → 153 600₽
  - Формула: `округлённое = floor(к_выплате / 100) × 100`
- **Хвост округления** сотрудника = `к_выплате_точное − округлённое` (всегда ≥ 0, т.к. вниз)
  - Пример: 110 407 − 110 400 = 7₽ (нет, floor до 100: 110 407 → 110 400, хвост 7). Уточнение: 110 407 → 110 400, хвост = 7. Верно.
- Округление применяется к ФИНАЛЬНОЙ сумме «К выплате» (после всех начислений, премий, удержаний). НЕ к промежуточным.
- Суммы округлены **окончательно** — это то что сотрудник получает. Хвост никуда не переносится (справочно).

## Где применяется

- В расчёте ЗП / ведомости — колонка «К выплате» показывает округлённую сумму
- В табеле (сводка) — «К выплате» округлённая
- В Excel-выгрузках — округлённая
- Везде где показывается финальная «К выплате» — округлённая вниз до 100

## Эффект округления на дашборде

- Новый показатель на дашборде: **«Эффект округления»** за выбранный период
- = сумма хвостов всех сотрудников: `Σ (к_выплате_точное − к_выплате_округлённое)`
- Показывает сколько всего «осело» из-за округления вниз (в пользу компании)
- Виден для admin и accountant (финансовый показатель). Manager — по своему отделу. Employee — не видит.
- Формат: карточка «Эффект округления: N₽» с пояснением (например «сумма округлений К выплате вниз до 100₽»)

## Распределение по компаниям и округление

Важный момент: если «К выплате» округляется, а распределение по компаниям считается от «Итого начислено» (не от «к выплате») — распределение НЕ затрагивается округлением «к выплате». Проверь: округление к выплате не должно ломать суммы распределения по компаниям (они от Итого начислено). Если распределение где-то считается от «к выплате» — там тоже учесть, но по нашей модели база распределения = Итого начислено, так что скорее всего независимо.

## Что НЕ менять

- Расчёт до «К выплате» (оклад, переработка, премии, удержания) — не трогать, только финальное округление
- Распределение по компаниям — от Итого начислено, не затрагивается
- Метод наибольшего остатка для распределения — отдельная логика, не путать с этим округлением
- Не рефакторить сверх задачи

## Acceptance criteria

1. «К выплате» округляется вниз до 100₽ везде (ведомость, табель, Excel).
2. Пример: 110 407 → 110 400, 26 826 → 26 800, 153 659 → 153 600.
3. Хвост = точное − округлённое, всегда ≥ 0.
4. На дашборде — карточка «Эффект округления» = сумма хвостов за период.
5. Эффект виден admin/accountant (свой отдел для manager), не employee.
6. Распределение по компаниям не сломано (от Итого начислено).
7. `pytest -v` зелёный, тесты: округление вниз до 100, хвост, сумма эффекта, распределение не затронуто.

## Подводные камни

- **Округление финальной суммы, не промежуточных** — округляем только «К выплате» в самом конце. Промежуточные (оклад, премии) остаются точными.
- **Хвост всегда ≥ 0** — округление вниз, так что точное всегда ≥ округлённого.
- **Итоговая строка** — сумма округлённых «К выплате», а не округление суммы. То есть сначала округлить каждого, потом сложить. (Σ округлённых, не floor(Σ точных).)
- **Эффект округления = Σ хвостов** — считается по всем сотрудникам периода.
- **Decimal** везде, floor до 100 корректно (не float-погрешности).
- **Не двойное округление** — если где-то уже было округление к выплате, не наслаивать.
