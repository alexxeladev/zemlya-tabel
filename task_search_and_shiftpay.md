## ПУНКТ 1 — Поиск сотрудников в табеле

**Проблема:** когда в отделе 100+ сотрудников, найти нужного в таблице табеля сложно.

**Решение:** поле поиска по ФИО в шапке табеля.
- Поле ввода «Поиск по ФИО» над таблицей
- По мере ввода — таблица фильтруется (показывает только сотрудников чьё ФИО содержит введённый текст, регистронезависимо)
- Пустое поле — показаны все
- Поиск работает поверх текущего фильтра отдела (если выбран отдел — ищем внутри него)
- Итоговые строки (ИТОГО, по компаниям) пересчитываются по отфильтрованным? Нет — оставь итоги по всем видимым сотрудникам отдела (поиск это навигация, не изменение расчёта). Или скрой итоги при активном поиске. На твой выбор что чище, но НЕ вводи пользователя в заблуждение неверными суммами.

Это чисто фронтовая фильтрация уже загруженных данных (не новый запрос на бэк), если объёмы позволяют. Если данные грузятся порциями — уточни у меня.

## ПУНКТ 2 — Посменная оплата (фикс за смену, без оклада)

### Суть

Новый тип оплаты сотрудника. У сотрудника нет месячного оклада. Его заработок = число отработанных смен × фикс-ставка за смену.

**Ключевой принцип:** у посменного меняется ТОЛЬКО способ расчёта базовой суммы (вместо оклада — смены × ставка). Всё остальное (переработка, отсутствия, премии, KPI, удержания, распределение по компаниям) работает по ОБЩИМ правилам, просто база другая.

### Тип оплаты в карточке сотрудника

Добавить выбор типа оплаты сотрудника:
- **Окладная** (текущая, по умолчанию) — есть месячный оклад
- **Посменная** — нет оклада, есть «ставка за смену» (фикс, Decimal)

При выборе «посменная» — поле оклада скрывается/не используется, появляется поле «Ставка за смену».

### Расчёт базовой суммы

- **Окладник:** как сейчас (оклад/норма × отработанные часы, cap на оклад).
- **Посменный:** `база = число_отработанных_смен × ставка_за_смену`
  - Смена = рабочий день по графику где сотрудник отработал (есть часы/отметка выхода)
  - Каждая отработанная смена = ставка, независимо рабочий день по графику или нет (доп. смена вне графика = ещё одна смена × ставка, БЕЗ ×1,5)
  - Эта сумма = «начислено оклад» в общей формуле (роль базы)

### Переработка / выход вне графика для посменных

- НЕТ отдельной переработки и НЕТ ×1,5 за выход вне графика
- Каждая смена (в графике или вне) оплачивается одинаково = ставка за смену
- То есть для посменных категории «переработка» и «праздничные/вне графика» не применяются — только смены × ставка

### Отсутствия (отпуск/больничный) для посменных

- Считаются по ОБЩИМ правилам, но вместо оклада используется **условный месячный оклад**:
  - `условный_оклад = ставка_за_смену × норма_смен_месяца`
  - где норма_смен_месяца — плановое число смен по графику сотрудника в этом месяце
  - Пример: ставка 2500, норма 15 смен → условный оклад 37500
- Формула отпуска/больничного та же: `условный_оклад / норма_часов × дни×8`
- Годовой лимит больничного (10 дней) — применяется так же

### Премии, KPI, удержания, распределение

- Всё как у окладников. «Итого начислено» = база (смены×ставка) + переработка(0 для посменных) + отпускные/больничные + премии + KPI.
- Удержания (займ, аванс) вычитаются как обычно.
- Распределение по компаниям (каскад: месяц% → карточка → отдел → по часам) — как обычно, от «итого начислено».

### Норма смен месяца

- Для посменного нужна «норма смен месяца» — сколько смен планово по его графику.
- Берётся из графика (число рабочих смен месяца по циклу/дням недели — та же логика что норма часов, но в сменах).
- Используется для условного оклада (отсутствия).

## Модель данных

- В карточке сотрудника: поле «тип оплаты» (окладная/посменная), поле «ставка за смену» (Decimal, nullable — только для посменных)
- Оклад остаётся nullable (у посменных пусто)
- Миграция, применить, alembic current = head

## Отображение

- В табеле/расчёте для посменного — вместо оклада показывать «посменно: N смен × ставка = сумма»
- Коэффициент/фикс выходных для посменного не применяется (у него смены равнозначны) — скрыть или показать «—»
- В ведомости — база корректно отражена

## Что НЕ делать

- Не трогать окладников (их расчёт не меняется)
- Не трогать другие механизмы (только добавить ветку для посменных)
- Не рефакторить сверх задачи

## Acceptance criteria

### Поиск
1. Поле поиска по ФИО в табеле, фильтрует по мере ввода, регистронезависимо.
2. Работает внутри выбранного отдела. Пустое поле — все.
3. Суммы не вводят в заблуждение (либо по всем, либо скрыты при поиске).

### Посменная оплата
4. В карточке — выбор типа оплаты (окладная/посменная). Посменная → поле «ставка за смену», оклад скрыт.
5. Посменный: база = смены × ставка. 15 смен × 2500 = 37500.
6. Доп. смена вне графика = ещё одна смена × ставка (без ×1,5). Переработки нет.
7. Отпуск/больничный посменного = от условного оклада (ставка × норма смен). Пример: ставка 2500, норма 15, отпуск 5 дней → условный оклад 37500, отпускные = 37500/норма_часов × 40.
8. Премии/KPI/удержания/распределение — работают как у окладников.
9. Окладники не сломаны.
10. `pytest -v` зелёный, тесты: база посменного, доп смена без ×1.5, условный оклад для отсутствий, распределение посменного, окладник не изменился.

## Подводные камни

- **Ветвление по типу оплаты** — везде где считается база от оклада, добавить ветку для посменных. Найди ВСЕ места (расчёт базы, отсутствия, условный оклад), не пропусти.
- **Норма смен** — нужна и для окладников (косвенно) и для посменных (условный оклад). Переиспользуй логику нормы графика.
- **Оклад nullable** — у посменных пусто, не должно падать где ожидается оклад.
- **Decimal** везде.
- **Миграция** — alembic upgrade head + проверка.
- **Отсутствия посменного** — условный оклад считается на лету из ставки и нормы смен, не хранить отдельно.
