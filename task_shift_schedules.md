## Два типа графиков

### Тип 1 — «по дням недели» (weekday-based)

Рабочие дни определяются днём недели. Праздники из производственного календаря — всё равно выходные (или по правилам, см. ниже).

Примеры:
- 5/2 стандарт: рабочие Пн-Пт (уже работает как standard)
- 6/1: рабочие Пн-Сб, выходной Вс (9ч/день)
- Пятидневка вс-чт: рабочие Вс, Пн, Вт, Ср, Чт; выходные Пт, Сб
- Пятидневка вт-сб: рабочие Вт-Сб; выходные Пн, Вс

Для этого типа у графика задаётся **набор рабочих дней недели** (например {Пн, Вт, Ср, Чт, Вс}).

**Норма** для weekday-графиков: считается по производственному календарю с учётом каких дней недели работает сотрудник (не обязательно Пн-Пт). Праздники исключаются.

### Тип 2 — «скользящий цикл» (cyclic shift)

Рабочие дни определяются циклом от стартовой даты, НЕ привязаны к дню недели и НЕ зависят от праздников (смена есть смена).

Примеры:
- 2/2 по 12ч: цикл «работа, работа, отдых, отдых» (длина 4)
- 3/3 по 12ч: цикл «работа×3, отдых×3» (длина 6)

Для этого типа у графика задаётся:
- **Стартовая дата** (anchor) — от неё отсчитывается цикл
- **Паттерн цикла** — например «2 рабочих + 2 выходных» или список [work, work, off, off]
- Часы за смену (12)

**Определение рабочего дня:** `offset = (дата − стартовая_дата).days`; `index = offset mod длина_цикла`; паттерн[index] → рабочий или выходной. Работает для любой даты в прошлом/будущем.

**Смена 1 и Смена 2** — это два ОТДЕЛЬНЫХ графика с разными стартовыми датами (сдвиг фазы). Например «2/2 смена 1» старт 1 июня, «2/2 смена 2» старт 3 июня (сдвиг на 2 дня → противофаза). Админ задаёт это при создании графика.

**Норма** для сменного графика: собственная «по графику» = число рабочих смен в месяце (по циклу) × часы смены. Например 2/2 в июне: 15 смен × 12 = 180ч. НЕ по производственному календарю. Переработка считается относительно ЭТОЙ нормы.

## Расчёт (payroll)

Ключевое изменение: сейчас норма считается только для standard через производственный календарь. Нужно обобщить:

1. **weekday-график**: норма = рабочие дни месяца (по дням недели графика, исключая праздники) × часы смены. С учётом сокращённых дней если применимо.

2. **cyclic-график**: норма = рабочие смены месяца (по циклу от стартовой даты) × часы смены. Производственный календарь НЕ влияет (смена в праздник всё равно смена).

3. `is_calculable` теперь True для всех типов (убрать заглушку для shift).

4. **Переработка** — от нормы соответствующего типа. По дням: `max(0, факт_дня − часы_смены_графика)`. Для 2/2 дневная норма 12, не 8.

5. Праздничные/выходные для сменника: день вне цикла (выходной цикла) в который он вышел — это переработка/праздничные? Уточнение: для cyclic-графика «выходной» это выходной ЦИКЛА. Если сотрудник вышел в свой выходной цикла — это сверхурочная работа. Обработать consistently с существующей логикой (день не по графику + есть часы → переработка или праздничные).

## Интерфейс

### Справочник графиков (создание/редактирование)

- Выбор типа: «По дням недели» / «Скользящий цикл»
- Для weekday: чекбоксы дней недели (Пн-Вс) + часы смены
- Для cyclic: стартовая дата (date picker) + паттерн (рабочих дней подряд / выходных подряд, например 2 и 2) + часы смены
- Превью: показать какие дни рабочие в текущем/выбранном месяце (визуально, чтобы админ проверил фазу)

### Табель

- Автозаполнение работает для всех графиков
- Норма сменника видна корректно (180 вместо 167)

## Что НЕ делать

- НЕ делать вахту (отдельный сложный график, позже)
- НЕ делать день/ночь смены (1 смена/2 смена — просто противофаза, оплата одинаковая, это разные графики со сдвигом)
- Не трогать распределение по компаниям, отсутствия, ночные смены
- Не рефакторить сверх задачи

## Подводные камни

- **Норма сменника ≠ производственный календарь** — не пытайся считать её через календарь. Считай по циклу графика за месяц.
- **Стартовая дата в прошлом** — цикл должен корректно вычисляться для любого месяца (mod арифметика от anchor).
- **Праздники для сменника не выходные** — смена в праздник это рабочая смена (в отличие от weekday-графика).
- **Обобщение is_calculable** — сейчас много мест завязано на «standard only». Найди все и обобщи, не пропусти.
- **Миграция** — alembic upgrade head + проверка.
- **Существующие 5/2** не должны сломаться — это weekday с Пн-Пт.
