# Задача 3.8 — Доработки после приёмочного тестирования

## Контекст

После задачи 3.7 (bugfix-спринт) при приёмочном тестировании выявлены три точечные правки. Логика сильно не меняется — просто корректируем то что в 3.7 ушло в одну сторону, а должно было — в другую.

Задача намеренно НЕ указывает имена конкретных функций или файлов. Сначала разберись в коде, потом точечно правь. Действуй по правилу 3 попыток.

## ПРАВКА 1 — Manager видит финансы своих сотрудников

**Сейчас:** В 3.7 финансовые колонки (Норма, Δ, Оклад, Сверхур., Праздн., Итого ₽) были скрыты для роли manager. Аналогично — страница «Расчёт ЗП» им недоступна.

**Должно быть:** Manager — это руководитель отдела, он отвечает за бюджет своих людей и должен видеть полную финансовую картину **по сотрудникам своего отдела**. Он не должен видеть финансы чужих отделов, но в рамках своего — видит всё как admin и accountant.

**Что нужно сделать:**

1. **В табеле**: финансовые колонки (Норма, Δ, Оклад, Сверхур., Праздн., Итого ₽) видны manager так же, как admin и accountant — но только для **видимых** сотрудников (своего отдела). Если manager попытается через API получить финансы чужого отдела — 403 как раньше.

2. **На странице «Расчёт ЗП»**: доступ открыт manager. Видит только сотрудников своего department_id (так же как в табеле). Если в его отделе нет сотрудников — пустое состояние.

3. **В дашборде**: если для admin/accountant были финансовые карточки — manager тоже их видит, по своему отделу.

4. **На бэке**: API расчёта ЗП должен включать manager в список разрешённых ролей, но возвращать только сотрудников его department_id (фильтрация принудительная, не доверяй фронту).

**Что НЕ менять:**
- Employee по-прежнему НЕ видит финансовых колонок (только свои часы)
- Manager НЕ видит финансы сотрудников чужих отделов
- Manager по-прежнему не может править справочники (отделы, компании, графики)

## ПРАВКА 2 — Manager видит и может редактировать своих сотрудников

**Сейчас:** В 3.7 страница «Сотрудники» либо скрыта от manager, либо показана в read-only режиме.

**Должно быть:** Manager видит **только сотрудников своего отдела** на странице «Сотрудники» и может редактировать **разрешённые поля** своих сотрудников.

**Разрешённые для manager поля:**
- ФИО
- Должность
- График работы (выбор из существующих)
- Оклад
- Дата приёма

**Запрещённые для manager поля** (только admin может менять):
- Отдел (manager не может переводить сотрудника в другой отдел или ИЗ своего отдела)
- Табельный номер
- Секция «Доступ в систему» (email, роль, пароль)
- Кнопки «Уволить», «Принять обратно»
- Создание нового сотрудника (manager только редактирует существующих)
- Удаление

**Что нужно сделать:**

1. В sidebar пункт «Сотрудники» должен быть виден manager (как был у admin).

2. На странице списка сотрудников для manager: видны только сотрудники с его department_id. Фильтр по отделам отсутствует (он у него один). Кнопка «Добавить сотрудника» отсутствует.

3. В форме редактирования карточки сотрудника для manager: разрешённые поля редактируются, запрещённые — disabled (с tooltip «Только администратор может изменить»). Кнопки «Уволить», «Сбросить пароль», «Отобрать доступ» — отсутствуют.

4. На бэке: PATCH `/api/employees/{id}` от manager — принимает только разрешённые поля. Все остальные игнорируются или возвращают 403 в зависимости от того что проще реализовать.

5. Manager не может изменить department_id — если в теле PATCH передан department_id с другим значением — 403. Если совпадает с текущим — игнорировать.

## ПРАВКА 3 — В Excel-выгрузке добавить итоги

**Сейчас:** Excel содержит таблицу с часами по дням, колонки половин месяца. Нет общего итога по сотруднику и переработки.

**Должно быть:** В Excel-файл добавлены **колонки итогов в конце таблицы** (после колонки «Итого за месяц» или вместо неё, или дополнительно — на твой выбор как красивее):

| Итого за месяц (часов) | в т.ч. переработка | Итого по компании А | Итого по компании Б | ... |

То есть:
- **Итого за месяц** — суммарные часы сотрудника по всем компаниям за месяц
- **Переработка** — количество часов переработки (свыше дневной нормы по графику, считается **по дням**, а не за весь месяц)
- **Итого по компании Х** — для каждой компании отдельная колонка с суммой часов на этой компании за месяц. Колонка генерируется на каждую компанию которая реально присутствует в данных за период.

**Расчёт переработки**: для каждого рабочего дня сравниваем фактические часы с дневной нормой сотрудника (`schedule.hours_per_shift`, для сокращённых — минус 1). Что выше — переработка этого дня. Суммируем по месяцу. Часы в выходные/праздники в эту колонку НЕ попадают (они в общем итоге, но это **праздничные**, а не переработка — в Excel мы их в отдельную колонку **не выделяем**).

**Что НЕ добавлять:**
- Финансы (оклад, рубли) в Excel НЕ выгружаем — это в 1С
- Праздничные часы отдельной колонкой пока НЕ выделяем — только переработка
- Норму отдельной колонкой не нужно (бухгалтер сам знает по графику)
